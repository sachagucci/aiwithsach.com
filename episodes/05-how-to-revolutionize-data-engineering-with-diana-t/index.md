## Summary

Sach talks with Josh Gray, co-founder and CEO of Artemis, a Vancouver startup that builds Diana, an AI agent working as a junior data engineer. Josh defines an AI agent as a smart helper that uses the software you already have and does the work, instead of waiting for you to fill in forms. He walks through a broken-pipeline example: Diana reads the error logs, finds the cause, writes the fix and opens a pull request in GitHub, showing every step along the way. On jobs, he relies on a argument from Box founder Aaron Levie: companies are capital constrained, so a team that gets more done earns more and ends up hiring more, not firing. He says AI agents make mistakes because the software is non-deterministic, so users need an interface that exposes every step and makes errors quick to fix. He describes knowledge graphs as a map that tells Diana where to look in a company's data models. Other topics include a healthcare client, a claim of 15 hours saved for 5 to 10 delegated tasks a week, a planned public benchmark for data engineering agents, and his advice to dive into AI now, since he sees real value being built behind the hype.

## Key takeaways

1. An AI agent is software that uses your existing tools and does the task, rather than a tool you have to fill in by hand.
2. Transparency matters most when AI changes code or does calculations: users need to see sources, steps and even the agent's own mistakes.
3. Agents are non-deterministic and will err, so the interface must make errors easy to spot and fix.
4. The case against layoffs: if a team gets more done with the same people, revenue grows and the team can grow too, though some small teams may still shrink.
5. Giving an AI context about your data models and warehouse, for example through a knowledge graph, is what lets it act like a veteran engineer.
6. Data engineering has few public evaluations for agents, unlike software engineering, which makes benchmarks a gap worth watching.
